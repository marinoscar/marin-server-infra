# Clipboard — Server Setup & Deployment

This document describes how to install and run **Clipboard** (universal clipboard web app) on the Ubuntu VPS using the existing `/opt/infra` infrastructure model.

It follows the same conventions as the rest of this repository:

* Root-operated server
* Docker Compose per app
* Nginx reverse proxy (Docker)
* No secrets committed to Git
* Deterministic, repeatable steps

This file is intended to be a **knowledge base / runbook** you can reuse or hand to an AI agent without additional context.

---

## 1. Prerequisites

Before installing Clipboard, the following must already be in place:

* Ubuntu VPS with `/opt/infra` initialized
* Docker + Docker Compose installed
* Shared Docker network `proxy` created
* Nginx reverse proxy running from `/opt/infra/proxy`
* Valid DNS record:
  * `clipboard.marin.cr` → VPS IP
* SSL certificate will be issued as part of this setup
* Git access to `github.com/marinoscar/clipboard`

If any of the above is missing, complete the base server and proxy setup first.

---

## 2. What is Clipboard

Clipboard is a universal clipboard web application that allows authenticated users to paste or upload any content (text, images, files, media) and access it across all devices in real-time. Items can be shared publicly via unique URLs.

### Architecture

Clipboard uses a multi-container stack:

| Component | Technology | Purpose |
|-----------|-----------|---------|
| **Web** | React 18, TypeScript, Material UI 5 | Frontend (static files via nginx:alpine) |
| **API** | NestJS 11, Fastify, TypeScript | Backend REST API + Socket.IO real-time sync |
| **Nginx** | nginx:alpine | Internal reverse proxy (routes `/api` → API, `/` → Web) |

### Key Features

* Paste (Ctrl+V), drag-and-drop, and file upload support
* Large file uploads (multi-GB) via S3 presigned multipart
* Real-time cross-device sync via Socket.IO
* Public sharing via unique URLs
* Google OAuth authentication with JWT tokens
* Installable PWA with Android Share Target support
* Configurable retention policies (archive/delete)
* SQLite database (file-based, no external DB server needed)

## 3. Directory Layout

Clipboard lives under:

```
/opt/infra/apps/clipboard
```

After installation, the structure looks like:

```
/opt/infra/apps/clipboard
├── .env                    # Environment file (NOT committed)
├── compose.yml             # Docker Compose file (generated by installer)
├── clipboard.conf          # Nginx proxy config (copied to proxy/nginx/conf.d/)
├── install-clipboard.sh    # Installation script
├── repo/                   # Cloned source code (NOT committed)
└── data/
    └── sqlite/             # Persistent SQLite database (NOT committed)
```

Key points:

* **`.env` contains all configuration** including JWT secrets, OAuth credentials, and S3 keys
* **`repo/` contains the cloned source** from `github.com/marinoscar/clipboard`
* **`data/sqlite/` stores the SQLite database** persistently
* **`clipboard.conf` is the proxy config** — copy it to the proxy directory after changes

## 5. Create the Environment File

```bash
nano /opt/infra/apps/clipboard/.env
```

Use the repo's template as a reference: `repo/infra/compose/.env.example`

Key variables:

```env
# Application
NODE_ENV=production
PORT=3000
APP_URL=https://clipboard.marin.cr

# Database (SQLite - file path inside container)
DATABASE_URL=file:/data/clipboard.db

# JWT Authentication

COOKIE_SECRET=CHANGE_ME           # generate with: openssl rand -hex 32
```

## 6. Docker Compose Configuration

The `compose.yml` is generated by `install-clipboard.sh` and defines three services:

```yaml
services:
  nginx:
    # Internal reverse proxy — routes /api → api, / → web
    ports:
      - "127.0.0.1:8320:80"
    mem_limit: (default)

  api:
    # NestJS backend — production build
    # Internal only (no public port)
    mem_limit: 512M
    cpus: 1.0

  web:
    # React frontend — static files via nginx:alpine
    # Internal only (no public port)
```

Key points:

* The `clipboard-nginx` container binds to `127.0.0.1:8320` (localhost only, not public)
* API and Web are internal-only (no port mappings, accessed via `clipboard-internal` network)
* Two networks: `clipboard-internal` (service-to-service) and `proxy` (shared VPS proxy network)
* SQLite data is bind-mounted from `./data/sqlite/` on the host

## 7. Installation

Use the provided installation script:

```bash
cd /opt/infra/apps/clipboard
chmod +x install-clipboard.sh
./install-clipboard.sh
```

The script performs these steps:

1. Creates data directories
2. Clones (or pulls) the Clipboard repository from `origin/main`
3. Validates `.env` exists
4. Generates `compose.yml` and `clipboard.conf`
5. Builds Docker images
6. Runs Prisma database migrations
7. Starts all services and verifies health

## 8. Configure Nginx Reverse Proxy

### 8.1 Fix the proxy configuration

The generated `clipboard.conf` may use Docker container names in `proxy_pass` directives. Since the VPS proxy runs in `network_mode: host`, it cannot resolve Docker DNS names. Ensure all `proxy_pass` directives use `127.0.0.1:8320`:

```bash
sed -i 's|proxy_pass http://clipboard-nginx;|proxy_pass http://127.0.0.1:8320;|g' \
  /opt/infra/apps/clipboard/clipboard.conf
```

### 8.2 Copy the proxy configuration

```bash
cp /opt/infra/apps/clipboard/clipboard.conf /opt/infra/proxy/nginx/conf.d/clipboard.conf
```

### 8.3 Proxy routing

The Nginx config routes traffic for `clipboard.marin.cr`:

| Path Pattern | Destination | Notes |
|-------------|-------------|-------|
| `/socket.io/*` | `127.0.0.1:8320` | WebSocket upgrade for real-time sync |
| `/api/*` | `127.0.0.1:8320` | API routes |
| `/*` | `127.0.0.1:8320` | React frontend static files |

Additional configuration:

* HSTS enabled with 1-year max-age
* Security headers: X-Frame-Options, X-Content-Type-Options, X-XSS-Protection, Referrer-Policy
* Client upload limit: unlimited (`client_max_body_size 0`) for multi-GB file support
* WebSocket support for Socket.IO (Upgrade + Connection headers)

### 8.4 Test and reload Nginx

```bash
docker exec proxy-nginx nginx -t
docker exec proxy-nginx nginx -s reload
```

## 9. Issue TLS Certificate

### 9.1 Issue the certificate

The default HTTP server (`00-default-http.conf`) already handles ACME challenges, so this can be run before deploying the clipboard proxy config:

```bash
docker run --rm \
  -v /opt/infra/proxy/letsencrypt:/etc/letsencrypt \
  -v /opt/infra/proxy/webroot:/var/www/certbot \
  certbot/certbot:latest certonly \
  --webroot -w /var/www/certbot \
  -d clipboard.marin.cr \
  --email oscar@marin.cr \
  --agree-tos \
  --no-eff-email
```

### 9.2 Verify certificate was issued

```bash
ls -la /opt/infra/proxy/letsencrypt/live/clipboard.marin.cr/
```

## 14. Troubleshooting

### A) API won't start: database error

**Cause:** SQLite file missing or wrong `DATABASE_URL`.

**Fix:**

1. Verify SQLite file exists: `ls -la /opt/infra/apps/clipboard/data/sqlite/`
2. Check `DATABASE_URL` in `.env` (should be `file:/data/clipboard.db`)
3. Check logs: `docker compose logs api`

### B) OAuth callback fails

**Cause:** `GOOGLE_CALLBACK_URL` doesn't match the URL configured in Google Cloud Console.

**Fix:** Ensure `GOOGLE_CALLBACK_URL=https://clipboard.marin.cr/api/auth/google/callback` in `.env` and matches Google OAuth settings exactly.

### C) WebSocket/Socket.IO not connecting

**Cause:** Nginx proxy not forwarding Upgrade headers.

**Fix:** Verify the `/socket.io/` location block in `clipboard.conf` includes `proxy_set_header Upgrade` and `proxy_set_header Connection "upgrade"`.

### D) Large file upload fails

**Cause:** Nginx body size limit or timeout too low.

**Fix:** Verify `client_max_body_size 0;` is set in `clipboard.conf` (0 = unlimited). For very large uploads, check S3 credentials and bucket configuration.

### E) Nginx proxy returns 502 Bad Gateway

**Cause:** `proxy_pass` using Docker container name instead of `127.0.0.1:8320`.

**Fix:** The VPS proxy runs in `network_mode: host` and cannot resolve Docker DNS. Ensure all `proxy_pass` directives in `clipboard.conf` use `http://127.0.0.1:8320`.

## 15. Security Considerations

* **JWT in memory only:** Access tokens are never stored in localStorage (XSS resistant)
* **httpOnly refresh cookies:** Refresh tokens use httpOnly, secure, SameSite=lax cookies (CSRF resistant)
* **Token rotation:** Refresh tokens are rotated on use with reuse detection
* **Google OAuth:** Authentication is handled externally via Google
* **HSTS enabled:** Browser enforcement of HTTPS
* **Security headers:** X-Frame-Options, X-Content-Type-Options, X-XSS-Protection, Referrer-Policy
* **S3 storage:** All file uploads go to S3 (never stored on the server filesystem)
* **Memory limits:** API container has enforced memory and CPU limits
