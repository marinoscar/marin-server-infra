# Neo4j Community + Nginx + Let's Encrypt (Ubuntu VPS) — `/opt/infra` Runbook

This runbook documents the **exact working** installation pattern for:

* **Neo4j 5 Community (Docker)** with APOC and Graph Data Science (GDS) plugins
* **Neo4j Browser UI** behind **Nginx reverse proxy** at **[https://graph.marin.cr](https://graph.marin.cr)**
* **Bolt protocol** reachable two ways:
  * **WSS over `443/tcp`** (default for the Browser — works on mobile carriers that block 7687)
  * **Raw Bolt over `7687/tcp`** (TLS terminated by Neo4j itself — for `cypher-shell` and driver libraries)
* **Nginx reverse proxy** running in Docker using **`network_mode: host`**
* **Let's Encrypt TLS** via **Certbot (webroot method)**, shared with all other apps

It mirrors the structure of `postgresql-setup.md` and is the **single source of truth** for future upgrades, re-installs, and onboarding.

> Operator preferences honored:
>
> * Use **nano**
> * Prefer explicit commands and verification after each step
> * No secrets committed to Git

---

## 0) Key architecture decisions

### Why Neo4j Community

* Free, self-hostable, supports core Cypher / APOC / GDS workloads.
* Aligns with the platform strategy: **Docker + Compose** for services.
* Version pinning (`neo4j:5-community` → latest 5.x LTS) for reproducibility.
* Persistence is a simple `./data/` bind mount, matching the Postgres pattern.

### Why Bolt is exposed publicly with TLS (not SSH-tunnel-only)

* The Neo4j Browser is loaded over HTTPS at `https://graph.marin.cr`.
* When the user clicks **Connect**, the Browser opens a WebSocket Secure (WSS) connection to Bolt.
* If Bolt were plain TCP/HTTP, the browser would block the connection due to mixed-content rules.

### Why Bolt is reached via WSS on port 443 (not direct on 7687)

* **Mobile carriers and corporate networks routinely block outbound port 7687** — connections silently time out after 30s with `ServiceUnavailable`.
* Nginx terminates TLS on `443/tcp` (standard HTTPS, always allowed) and forwards WebSocket upgrades to Neo4j's Bolt port on `127.0.0.1:7687`.
* The Bolt port still listens publicly on `7687` with its own TLS for direct drivers (`cypher-shell`, Python `neo4j` driver, etc.) — those clients use raw TCP Bolt and don't need WebSocket framing.
* `NEO4J_server_bolt_advertised__address` is set to `graph.marin.cr:443` so the Browser's Connect dialog auto-fills the WSS endpoint.

### Why Neo4j ALSO manages its own Bolt TLS on 7687

* Keeps `cypher-shell` and direct driver access available with raw Bolt over TLS (no WebSocket overhead).
* Cert renewal hook is a simple `cp + chown + docker restart` (see §5.3).
* Direct clients can specify the explicit `:7687` port to bypass the WSS proxy when needed.

### Critical constraint: Nginx runs in `network_mode: host`

* When Nginx runs with `network_mode: host`, it **cannot use Docker DNS**.
* That means `proxy_pass http://infra-neo4j:7474;` will fail.

✅ **Solution:** bind Neo4j Browser on `127.0.0.1:7474` and proxy Nginx to localhost. Bolt is bound to `0.0.0.0:7687` (publicly reachable for direct drivers), AND nginx routes WebSocket upgrades from `443` to `127.0.0.1:7687` so the Browser can talk to Bolt over standard HTTPS port.

### Nginx routing strategy (port 443)

A single `location /` proxies to one of two upstreams based on `$http_upgrade`:

```nginx
map $http_upgrade $neo4j_upstream_port {
    default   7474;   # Browser UI (HTTP requests)
    websocket 7687;   # Bolt (WebSocket upgrade)
}

server {
    listen 443 ssl;
    ...
    location / {
        proxy_pass http://127.0.0.1:$neo4j_upstream_port;
        proxy_http_version 1.1;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        ...
    }
}
```

The Neo4j Bolt server on `7687` natively accepts both raw Bolt TCP **and** WebSocket upgrades on the same port — when nginx sends `Upgrade: websocket`, Bolt replies with `101 Switching Protocols` and switches into WebSocket-framed Bolt.

  * `22/tcp` (SSH)
  * `80/tcp` (HTTP — ACME challenges + redirect)

  * `7687/tcp` (Neo4j Bolt — added by `install-neo4j.sh`)

Verify:

```bash
ufw status verbose
```

### Other

* `proxy-nginx` container running (`/opt/infra/proxy/`)
* Docker + Docker Compose installed
* Operating as `root`

## 2) Folder layout

We follow the rule: **one app = one folder = one Compose file**.

```
/opt/infra/apps/neo4j/
├── compose.yml         (committed — generated by install-neo4j.sh)
├── .env                (NOT committed — secrets)
├── graph.conf          (committed — nginx vhost template)
├── install-neo4j.sh    (committed — end-to-end installer)
├── sync-certs.sh       (committed — copies LE cert with uid 7474 ownership)
├── data/               (NOT committed — graph storage)
├── logs/               (NOT committed)
├── plugins/            (NOT committed — APOC + GDS jars, auto-downloaded)
├── conf/               (NOT committed — neo4j.conf overrides if any)
├── ssl/                (NOT committed — fullchain.pem + privkey.pem, chown 7474:7474)
│   ├── trusted/        (required by Neo4j SSL policy validator, empty)
│   └── revoked/        (required by Neo4j SSL policy validator, empty)
└── backups/            (NOT committed — manual neo4j-admin dump output)
```

`data/`, `logs/`, `plugins/`, `conf/`, `backups/` are owned by uid 7474 once Neo4j first writes to them (the container `neo4j` user). Don't `chown` them back to root.

Create the structure:

```bash
mkdir -p /opt/infra/apps/neo4j/{data,logs,plugins,conf,ssl/trusted,ssl/revoked,backups}
cd /opt/infra/apps/neo4j
```

## 4) The `compose.yml` walk-through

The compose file lives at `/opt/infra/apps/neo4j/compose.yml` and is generated by the installer. Key elements:

| Element | Value | Why |
|---|---|---|
| `image` | `neo4j:5-community` | Latest 5.x LTS, pinned to major version |
| `container_name` | `infra-neo4j` | Matches the `infra-*` naming used by postgres |
| `restart` | `unless-stopped` | Survives reboots, allows manual stop |
| `127.0.0.1:7474:7474` | Browser UI | Bound to localhost — proxied by nginx |
| `0.0.0.0:7687:7687` | Bolt | Public — needed for browser query traffic |
| `NEO4J_PLUGINS` | `["apoc","graph-data-science"]` | Image auto-downloads jars on first start |
| `NEO4J_dbms_security_procedures_unrestricted` | `apoc.*,gds.*` | Required for procedures like `apoc.export.*`, `gds.*` |
| `NEO4J_server_memory_heap_max__size` | `2G` | Tune to host (see `neo4j-admin server memory-recommendation`) |
| `NEO4J_server_bolt_advertised__address` | `graph.marin.cr:7687` | What the Browser hands to the user as the Bolt URL |
| `NEO4J_server_bolt_tls__level` | `OPTIONAL` | Allow both `bolt://` and `neo4j+s://` (clients negotiate) |
| `./data:/data` | Graph storage | Bind mount (matches postgres pattern) |
| `./ssl:/ssl:ro` | Cert directory | Populated by `sync-certs.sh` |

### Neo4j env-var encoding rules

The Docker image translates env vars to `neo4j.conf` properties:

| Property | Env var |
|---|---|
| `server.bolt.tls_level` | `NEO4J_server_bolt_tls__level` |
| `dbms.ssl.policy.bolt.enabled` | `NEO4J_dbms_ssl_policy_bolt_enabled` |
| `server.memory.heap.max_size` | `NEO4J_server_memory_heap_max__size` |

Rules: `.` → `_`, single `_` in the property name → `__` (double underscore).

## 5) Bolt TLS / certificates

### 5.1 Why a separate `./ssl/` directory

Let's Encrypt files in `/opt/infra/proxy/letsencrypt/live/graph.marin.cr/` are:

* Symlinks (Neo4j's SSL policy validator does not always resolve symlinks cleanly)
* Owned by `root`
* `privkey.pem` is `chmod 600`

Neo4j runs as uid **7474** inside the container and cannot read the original files. `sync-certs.sh` solves this by copying the real files, chowning them to `7474:7474`, and placing them in a directory Neo4j mounts read-only.

### 5.2 `sync-certs.sh`

```bash
#!/usr/bin/env bash
set -euo pipefail
NEO4J_DIR="/opt/infra/apps/neo4j"
DOMAIN="graph.marin.cr"
LE_LIVE="/opt/infra/proxy/letsencrypt/live/${DOMAIN}"

mkdir -p "${NEO4J_DIR}/ssl/trusted" "${NEO4J_DIR}/ssl/revoked"
cp -L "${LE_LIVE}/fullchain.pem" "${NEO4J_DIR}/ssl/fullchain.pem"
cp -L "${LE_LIVE}/privkey.pem"   "${NEO4J_DIR}/ssl/privkey.pem"
chown -R 7474:7474 "${NEO4J_DIR}/ssl"
chmod 644 "${NEO4J_DIR}/ssl/fullchain.pem"
chmod 600 "${NEO4J_DIR}/ssl/privkey.pem"
```

✅ **Lesson learned:** The empty `trusted/` and `revoked/` directories **must exist** — Neo4j's SSL policy validator refuses to start otherwise (`base_directory missing required subdirectories`).

### 5.3 Renewal hook

The shared renewal cron (`/opt/infra/shared/renew-all-certs.sh`) handles the actual cert renewal centrally. After that runs, a Neo4j-specific tail re-syncs the cert and restarts the container (Neo4j does not hot-reload SSL):

```bash
# In /opt/infra/shared/renew-all-certs.sh, after the nginx reload:
GRAPH_CERT="/opt/infra/proxy/letsencrypt/live/graph.marin.cr/fullchain.pem"
if [ -f "${GRAPH_CERT}" ] && [ "${GRAPH_CERT}" -nt "/opt/infra/apps/neo4j/ssl/fullchain.pem" ]; then
  /opt/infra/apps/neo4j/sync-certs.sh >> "${LOG}" 2>&1
  docker restart infra-neo4j >> "${LOG}" 2>&1 || true
  echo "Refreshed Neo4j SSL and restarted container" >> "${LOG}"
fi
```

The `-nt` test makes this a no-op on the (vast majority of) days when the cert wasn't renewed.

## 6) Nginx vhost

File: `/opt/infra/apps/neo4j/graph.conf` (deployed to `/opt/infra/proxy/nginx/conf.d/graph.conf`).

The vhost routes a single `location /` to a variable upstream port based on `$http_upgrade` (see §0 routing strategy). The global `$connection_upgrade` map is defined once in `/opt/infra/proxy/nginx/conf.d/05-websocket-map.conf` — this vhost just references it.

```nginx
map $http_upgrade $neo4j_upstream_port {
    default   7474;
    websocket 7687;
}

server {
    listen 443 ssl;
    http2 on;
    server_name graph.marin.cr;

    ssl_certificate     /etc/letsencrypt/live/graph.marin.cr/fullchain.pem;
    ssl_certificate_key /etc/letsencrypt/live/graph.marin.cr/privkey.pem;

    location / {
        proxy_pass http://127.0.0.1:$neo4j_upstream_port;
        proxy_http_version 1.1;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
        proxy_set_header Upgrade $http_upgrade;
        proxy_set_header Connection $connection_upgrade;
        proxy_read_timeout 3600;
        proxy_send_timeout 3600;
    }
}
```

The 1h read/send timeouts match Neo4j's idle-connection behavior — important for long-lived Bolt sessions.

## 7) Install procedure

### 7.1 One-shot installer (recommended)

```bash
cd /opt/infra/apps/neo4j
nano .env                   # set NEO4J_AUTH=neo4j/<password>
sudo ./install-neo4j.sh
```

The installer:

1. Creates missing directories.
2. Validates `.env` has a valid `NEO4J_AUTH`.
3. Issues a Let's Encrypt cert for `graph.marin.cr` (if missing) using a temporary HTTP-only nginx vhost.
4. Runs `sync-certs.sh` to copy the cert into `./ssl/` with uid 7474 ownership.
5. `docker compose up -d`.
6. Polls `cypher-shell ... 'RETURN 1'` until Neo4j answers (allow ~60–90s for first-start plugin download).
7. Copies `graph.conf` into the proxy and reloads nginx.
8. Runs `ufw allow 7687/tcp`.
9. Smoke-tests local + public + Bolt-TLS endpoints.

### 7.2 Manual procedure

If you prefer step-by-step (e.g. for re-installs on a fresh host):

```bash
# 1. Folder + secrets
mkdir -p /opt/infra/apps/neo4j/{data,logs,plugins,conf,ssl/trusted,ssl/revoked,backups}
cd /opt/infra/apps/neo4j
echo "NEO4J_AUTH=neo4j/$(openssl rand -hex 24)" > .env
chmod 600 .env

# 2. Issue cert (deploy temporary HTTP-only config first, then run certbot)
docker run --rm \
  -v /opt/infra/proxy/letsencrypt:/etc/letsencrypt \
  -v /opt/infra/proxy/webroot:/var/www/certbot \
  certbot/certbot:latest certonly \
  --webroot -w /var/www/certbot \
  -d graph.marin.cr \
  --email oscar@marin.cr --agree-tos --no-eff-email

# 3. Sync certs and start
./sync-certs.sh
docker compose up -d

# 4. Wait for Neo4j to come up (~60-90s on first start due to plugin download)
docker logs --tail 50 -f infra-neo4j        # Ctrl-C when you see "Started."

# 5. Install nginx vhost
cp graph.conf /opt/infra/proxy/nginx/conf.d/graph.conf
docker exec proxy-nginx nginx -t
docker exec proxy-nginx nginx -s reload

# 6. Open firewall
ufw allow 7687/tcp comment "Neo4j Bolt"
```

## 8) Verification

```bash
# Containers
docker ps --format "table {{.Names}}\t{{.Status}}\t{{.Ports}}"
# Expect:
#   infra-neo4j   Up    127.0.0.1:7474->7474/tcp, 0.0.0.0:7687->7687/tcp

# Browser UI locally
curl -sI http://127.0.0.1:7474/         # expect 200

# Browser UI through nginx
curl -sI https://graph.marin.cr/        # expect 200

# Bolt TLS reachable from outside (direct 7687)
openssl s_client -connect graph.marin.cr:7687 -servername graph.marin.cr </dev/null 2>/dev/null | head -20
# expect: CONNECTED, valid cert chain for graph.marin.cr

# WebSocket-over-443 upgrade reachable (what the Browser uses)
# Note: MUST be GET, not HEAD — Neo4j's WebSocket handler ignores HEAD requests
curl --http1.1 -i -X GET \
    -H "Connection: Upgrade" -H "Upgrade: websocket" \
    -H "Sec-WebSocket-Version: 13" \
    -H "Sec-WebSocket-Key: $(openssl rand -base64 16)" \
    -H "Sec-WebSocket-Protocol: bolt" \
    --max-time 3 https://graph.marin.cr/ 2>&1 | head -5
# expect: HTTP/1.1 101 Switching Protocols + upgrade: websocket

# Cypher works (from inside the container, to test both auth and SSL)
docker exec infra-neo4j cypher-shell -u neo4j -p '<password>' 'RETURN 1 AS ok'

# Cypher over direct Bolt (7687) — for clients with explicit port
docker exec infra-neo4j cypher-shell -a 'neo4j+s://graph.marin.cr:7687' \
    -u neo4j -p '<password>' 'RETURN 1 AS ok'

# Plugins loaded
docker exec infra-neo4j cypher-shell -u neo4j -p '<password>' \
    "CALL dbms.procedures() YIELD name WHERE name STARTS WITH 'apoc' OR name STARTS WITH 'gds' RETURN count(name)"
# expect: a number in the hundreds

# UFW
ufw status verbose | grep -E '7687|443|80'
```

**Browser sanity check:** open `https://graph.marin.cr` in a desktop browser. The Neo4j Browser loads, prompts for credentials, and after login `:server status` should report `Connected as neo4j to neo4j+s://graph.marin.cr:7687`.

## 10) Day-2 operations

### 10.1 Backups (manual)

Backups follow the postgres model: no cron, operator runs on demand.

**Online dump (Neo4j 5 supports this):**

```bash
docker exec infra-neo4j neo4j-admin database dump neo4j \
    --to-path=/backups \
    --overwrite-destination=true
ls -lh /opt/infra/apps/neo4j/backups/
```

**Offline dump (smaller files, requires downtime):**

```bash
docker compose stop neo4j
docker compose run --rm neo4j neo4j-admin database dump neo4j --to-path=/backups
docker compose start neo4j
```

Copy off-host:

```bash
rsync -av /opt/infra/apps/neo4j/backups/ user@backup-host:/path/to/neo4j-backups/
```

### 10.2 Restore

```bash
docker compose stop neo4j
docker compose run --rm neo4j neo4j-admin database load neo4j \
    --from-path=/backups --overwrite-destination=true
docker compose start neo4j
```

### 10.3 Plugin upgrade

The image auto-downloads plugins for the image's Neo4j version. To force a refresh:

```bash
cd /opt/infra/apps/neo4j
rm -rf plugins/*
docker compose up -d --force-recreate neo4j
docker logs --tail 100 -f infra-neo4j     # watch for "Installing Plugin ..."
```

### 10.4 Version bump (minor, e.g. 5.26 → 5.27)

```bash
cd /opt/infra/apps/neo4j
docker compose pull
docker compose down
docker compose up -d
```

Store-format upgrades within Neo4j 5.x are automatic.

### 10.5 Password rotation

```bash
docker exec -it infra-neo4j cypher-shell -u neo4j -p '<old>' \
    "ALTER CURRENT USER SET PASSWORD FROM '<old>' TO '<new>'"

# Update .env so future docker compose up uses the new password
nano /opt/infra/apps/neo4j/.env
```

`NEO4J_AUTH` is only consumed on the very first start — changing the env var on a running database has no effect.

### 10.6 Memory tuning

```bash
docker exec infra-neo4j neo4j-admin server memory-recommendation
```

Use the output to adjust the three memory env vars in `compose.yml`, then `docker compose up -d --force-recreate neo4j`.

## 11) Troubleshooting quick reference

### A) `ServiceUnavailable: Failed to establish connection in 30000ms` from Browser

**Cause:** The Browser is trying to reach Bolt and the route is blocked.
**Fix:** Look at the Connect URL field in the Browser:
  * If it shows `bolt+s://graph.marin.cr:7687` and you're on a mobile carrier — the carrier is blocking 7687. Change the URL to `bolt+s://graph.marin.cr:443` (the WSS-over-443 route through nginx). The advertised address should already be `:443` after install; if the Browser cached an old `:7687` URL, edit it manually.
  * If it shows `:443` and still fails — verify `curl --http1.1 -X GET -H "Connection: Upgrade" -H "Upgrade: websocket" -H "Sec-WebSocket-Version: 13" -H "Sec-WebSocket-Key: x" -H "Sec-WebSocket-Protocol: bolt" https://graph.marin.cr/ -i` returns `101 Switching Protocols`. If not, check nginx config and `docker exec proxy-nginx nginx -t`.

### B) Browser console shows `Mixed Content` errors

**Cause:** Browser is loaded over HTTPS but is trying to connect to plain `bolt://` (port not TLS).
**Fix:** Connect dropdown should show `neo4j+s://graph.marin.cr:7687`. If it shows `bolt://`, check that `NEO4J_server_bolt_advertised__address` is set correctly and that Bolt SSL policy env vars are present in `compose.yml`.

### C) `Could not load private key` on Neo4j start

**Cause:** `./ssl/privkey.pem` is not readable by uid 7474.
**Fix:** Re-run `sync-certs.sh`. Verify with `ls -l /opt/infra/apps/neo4j/ssl/` — fullchain should be `7474:7474 644`, privkey should be `7474:7474 600`.

### D) `502 Bad Gateway` on `https://graph.marin.cr`

**Cause:** Neo4j container is not running, or not bound to `127.0.0.1:7474`.
**Fix:** `docker ps | grep neo4j`. Restart with `docker compose up -d`. If it's running but nginx still 502s, `docker restart proxy-nginx`.

### E) APOC / GDS procedures missing

**Cause:** Plugins did not auto-install, or `procedures.unrestricted` / `procedures.allowlist` env vars are missing.
**Fix:** Check `docker logs infra-neo4j | grep -i plugin`. Verify the env vars in `compose.yml`. Clear `./plugins/` and `--force-recreate` to force re-download.

### F) Neo4j refuses to start: `Required SSL policy directory missing`

**Cause:** `./ssl/trusted/` or `./ssl/revoked/` doesn't exist.
**Fix:** `mkdir -p /opt/infra/apps/neo4j/ssl/{trusted,revoked} && chown -R 7474:7474 /opt/infra/apps/neo4j/ssl/`.

### G) "Database is read only" after disk full

**Cause:** Neo4j flips to read-only when disk fills, doesn't auto-recover.
**Fix:** Free space, then `docker restart infra-neo4j`. The graph is intact — Neo4j 5 has crash-safe WAL.

## 12) Lessons learned

(Add post-install discoveries here over time, in the style of `postgresql-setup.md` §8.)

* The `trusted/` and `revoked/` subdirectories under `./ssl/` are **mandatory** even if you don't use mTLS — Neo4j's SSL policy validator requires them.
* Neo4j stores credentials inside the graph after first start. Changing `NEO4J_AUTH` in `.env` later does nothing — use `ALTER CURRENT USER` instead.
* Plugin auto-download on first start can take 60–90s on a slow link; the healthcheck handles this with `start_period: 90s`.
* **Mobile carriers and corporate networks routinely block outbound port 7687.** The Browser must use WSS-over-443 to work on those networks. The `$http_upgrade`-keyed map in `graph.conf` makes a single port (443) serve both the Browser UI and Bolt-over-WebSocket without conflict.
* Neo4j's Bolt server on `7687` natively accepts WebSocket upgrades (returns `101 Switching Protocols`), but only for `GET` requests. `HEAD` requests get dropped silently — surfaces as nginx `502 Bad Gateway` if you smoke-test with `curl -I`. Use `curl -X GET` instead.
